## CONTEXT

The migration runner currently derives the expected PHP class name from the migration filename (e.g. `0001-add-meetings-schema.php → Bookit_Migration_0001_Add_Meetings_Schema`). Because PHP class names are global across the WordPress runtime, two extension plugins with a file named `0001-*.php` will have a class name collision. Extensions currently work around this with `class_alias()`. This task eliminates the filename→classname coupling entirely: after `require_once`-ing the file, the runner scans all declared classes for one that extends `Bookit_Migration_Base`, matches the expected `migration_id()` and `plugin_slug()`, and uses that — regardless of what the class is named.

```php
/**
 * Find a migration class that was just loaded from a file.
 *
 * After requiring a migration file, scan all declared classes for one
 * that: (a) extends Bookit_Migration_Base, (b) returns the expected
 * migration_id() and plugin_slug() values.
 *
 * @param string $expected_migration_id The migration ID to match.
 * @param string $plugin_slug           The plugin slug to match.
 * @return string|null Class name, or null if not found.
 */
private static function find_migration_class(
    string $expected_migration_id,
    string $plugin_slug
): ?string {
    foreach ( get_declared_classes() as $class ) {
        if ( ! is_subclass_of( $class, Bookit_Migration_Base::class ) ) {
            continue;
        }
        $instance = new $class();
        if (
            $instance->migration_id() === $expected_migration_id &&
            $instance->plugin_slug()  === $plugin_slug
        ) {
            return $class;
        }
    }
    return null;
}
```
