## CONTEXT

Two cosmetic layout issues were observed during Sprint 2 housekeeping and confirmed during Sprint 2.5 Task 2 verification. Neither is a regression — both pre-existed the mount point fix. The extension Vue app (`#bookit-meetings-app`) mounts inside core's layout via the `bookit_dashboard_extension_content` hook. Two issues exist:

1. **Nav sidebar overlaps the Vue app** in desktop view — z-index or positioning conflict between core's sidebar and the `#bookit-meetings-app` container
2. **Blank space above content** — the `.bm-app` wrapper has `padding: 24px` which adds visible empty space on every dashboard page where the extension mounts (not just the meetings settings page)

All CSS fixes must be scoped to `#bookit-meetings-app` — never override core sidebar styles globally.

## IMPLEMENTATION REQUIREMENTS

### `bookit-meetings/dashboard/src/App.vue` — MODIFY

**Fix 1 — Remove padding from `.bm-app` wrapper:**

The `.bm-app` scoped style currently has:
```css
.bm-app {
  padding: 24px;
  color: var(--bookit-text-primary);
}
```

The `padding: 24px` causes a visible blank area on every dashboard page where `#bookit-meetings-app` is mounted (all dashboard pages, not just `/meetings`). `BookingDetailView` renders nothing visible until a booking is detected, so the padding creates an empty white box at the bottom of every page.

Remove the padding from `.bm-app`:
```css
.bm-app {
  color: var(--bookit-text-primary);
}
```

The settings page content (`SettingsView`) has its own internal padding and does not need padding from the wrapper.

**Fix 2 — Sidebar overlap:**

Before writing any CSS, inspect the rendered DOM in browser dev tools to identify the exact elements causing the overlap. Specifically:

- What is the `z-index` of core's sidebar element?
- What is the position (`fixed`, `absolute`, `relative`) of core's sidebar?
- What is the position and `z-index` of `#bookit-meetings-app`?

Based on what you find, add a scoped CSS rule to the **unscoped** `<style>` block in `App.vue` (the block that already defines `#bookit-meetings-app { ... }`) to fix the overlap. The fix must:

- Only target `#bookit-meetings-app` — never override core sidebar styles globally
- Not use `!important` unless absolutely necessary
- Not break core dashboard pages

If after reading the files the sidebar overlap is caused by `#bookit-meetings-app` having a higher `z-index` than core's sidebar, fix by removing or lowering the `z-index` on `#bookit-meetings-app`. If it's caused by core's sidebar having a lower `z-index` than the extension container, fix by setting an appropriate `z-index` on `#bookit-meetings-app` only.

**Do not touch core's sidebar CSS under any circumstances.**
