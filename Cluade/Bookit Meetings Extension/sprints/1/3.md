## CONTEXT

This task creates the REST API layer for Bookit Meetings: three endpoints
under the `bookit-meetings/v1` namespace. All endpoints are admin-only —
staff users must be blocked. The settings endpoints read and write the three
settings rows inserted by the Task 2 migration. The link endpoint allows an
admin to manually set or clear the `meeting_link` on any booking row.

No Vue work in this task. The endpoints will be consumed by the Vue dashboard
in Sprint 2.

### `bookit-meetings/api/class-meetings-api.php` — CREATE

- Class name: `Bookit_Meetings_Api`
- Single public method: `register_routes(): void`
- Copy the `check_dashboard_permission()` and `check_admin_permission()`

- All three endpoints are **admin-only** — use `check_admin_permission` as
  the `permission_callback`, not `check_dashboard_permission`

**Endpoints to register:**

#### `GET bookit-meetings/v1/settings`

- Permission: admin only
- Reads all three settings keys from `{prefix}bookings_settings`:
  `meetings_enabled`, `meetings_platform`, `meetings_manual_url`
- Read via direct `$wpdb->get_col()` query (not `get_var()`) — settings
  values may be empty strings; `get_var()` returns `null` for `''`
- Response envelope:
  ```json
  {
    "success": true,
    "data": {
      "meetings_enabled": "0",
      "meetings_platform": "",
      "meetings_manual_url": ""
    }
  }
  ```
- If a key is missing from the table, return its default value:
  `meetings_enabled` → `"0"`, `meetings_platform` → `""`,
  `meetings_manual_url` → `""`

#### `POST bookit-meetings/v1/settings`

- Permission: admin only
- Accepts JSON body with any subset of the three keys
- Validate each key individually:
  - `meetings_enabled` → must be `"0"` or `"1"` (string)
  - `meetings_platform` → must be one of: `"whatsapp"`, `"teams"`,
    `"generic"`, `""` (empty string = not set)
  - `meetings_manual_url` → if present and non-empty, must pass
    `filter_var( $value, FILTER_VALIDATE_URL )` — return 422 if invalid
- Upsert each provided key using:
  ```php
  $wpdb->query( $wpdb->prepare(
      "INSERT INTO {$wpdb->prefix}bookings_settings (setting_key, setting_value)
       VALUES (%s, %s)
       ON DUPLICATE KEY UPDATE setting_value = VALUES(setting_value)",
      $key, $value
  ) );
  ```
- Return the full updated settings object after saving (same shape as GET)
- On validation error return:
  ```json
  { "code": "bookit_meetings_invalid_setting", "message": "...", "data": { "status": 422 } }
  ```

#### `POST bookit-meetings/v1/bookings/{id}/link`

- Permission: admin only
- URL param: `id` (integer, required) — the booking ID
- Accepts JSON body: `{ "meeting_link": "https://..." }` or
  `{ "meeting_link": "" }` to clear
- Validate:
  - `id` must be a positive integer
  - `meeting_link` if non-empty must pass `filter_var( $value, FILTER_VALIDATE_URL )`
  - booking must exist in `{prefix}bookings` and not be soft-deleted
    (`deleted_at IS NULL`) — return 404 if not found
- Update `meeting_link` column:
  ```php
  $wpdb->update(
      $wpdb->prefix . 'bookings',
      [ 'meeting_link' => $meeting_link ?: null ],
      [ 'id' => $booking_id ],
      [ '%s' ],
      [ '%d' ]
  );
  ```
  Empty string `""` should be stored as `NULL` (use `$meeting_link ?: null`)
- Response on success:
  ```json
  {
    "success": true,
    "data": {
      "booking_id": 42,
      "meeting_link": "https://teams.microsoft.com/..."
    }
  }
  ```
- On validation error return 422; on not found return 404
