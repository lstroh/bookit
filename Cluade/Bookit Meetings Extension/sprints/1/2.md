## CONTEXT

This task creates all database changes required by Bookit Meetings:
a `meeting_link` column on `wp_bookings`, a `wp_bookit_meetings_credentials`
table (empty in Phase 1, ready for Phase 2 OAuth), and three settings rows
in `wp_bookings_settings` (`meetings_enabled`, `meetings_platform`,
`meetings_manual_url`). All changes are delivered as a single migration file
with `up()` and `down()` methods. The activation and deactivation stubs left
in Task 1 must be filled in as part of this task.

### `bookit-meetings/database/migrations/0001-add-meetings-schema.php` — CREATE

- Class name: `Bookit_Migration_0001_Add_Meetings_Schema`
- Extend `Bookit_Migration_Base`
- `migration_id()` returns: `'0001-add-meetings-schema'`
- `plugin_slug()` returns: `'bookit-meetings'`

**`up()` must perform these operations in order:**

1. **Add `meeting_link` column to `{prefix}bookings`:**
   - Check column existence using `information_schema.COLUMNS` — NEVER `SHOW COLUMNS LIKE`
   - Only `ALTER TABLE` if the column does not exist
   - Column definition: `meeting_link VARCHAR(500) NULL DEFAULT NULL`

2. **Create `{prefix}bookit_meetings_credentials` table:**
   - Check table existence using `information_schema.TABLES` — NEVER `SHOW TABLES LIKE`
   - Only `CREATE TABLE` if it does not exist
   - Schema:
     ```sql
     CREATE TABLE {prefix}bookit_meetings_credentials (
         id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
         platform    VARCHAR(50)  NOT NULL,
         credential_key   VARCHAR(100) NOT NULL,
         credential_value TEXT         NOT NULL,
         created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
         updated_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
         UNIQUE KEY platform_key (platform, credential_key)
     ) ENGINE=InnoDB {$charset};
     ```
   - `$charset` must use `$wpdb->get_charset_collate()`

3. **Insert the three settings rows into `{prefix}bookings_settings`:**
   - Use `$wpdb->query( $wpdb->prepare( ... ) )` with `INSERT IGNORE` so re-running `up()` is idempotent
   - Rows to insert:

     | setting_key | setting_value |
     |---|---|
     | `meetings_enabled` | `'0'` |
     | `meetings_platform` | `''` |
     | `meetings_manual_url` | `''` |

   - Process each row individually in a loop — do NOT use a single bulk INSERT

**`down()` must be the exact inverse of `up()` in reverse order:**

1. Delete the three settings rows from `{prefix}bookings_settings`:
   ```sql
   DELETE FROM {prefix}bookings_settings
   WHERE setting_key IN ('meetings_enabled', 'meetings_platform', 'meetings_manual_url')
   ```
   Process each key individually in a loop using `$wpdb->delete()` — not a single bulk DELETE

2. Drop `{prefix}bookit_meetings_credentials` table:
   ```sql
   DROP TABLE IF EXISTS {prefix}bookit_meetings_credentials
   ```

3. Drop `meeting_link` column from `{prefix}bookings`:
   ```sql
   ALTER TABLE {prefix}bookings DROP COLUMN IF EXISTS meeting_link
   ```

**Critical rules for this file:**
- All table/column existence checks use `information_schema` only
- All tables use `ENGINE=InnoDB` and `$wpdb->get_charset_collate()`
- No `JSON_CONTAINS()` anywhere in this file
- Add `// phpcs:ignore WordPress.DB.PreparedSQL.NotPrepared` on every raw `$wpdb->query()` call
- Add `// phpcs:ignore WordPress.DB.DirectDatabaseQuery.DirectQuery` where needed
