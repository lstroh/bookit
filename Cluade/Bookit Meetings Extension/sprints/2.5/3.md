## CONTEXT

Core v1.5.1 `booking-confirmed-v2.php` now re-fetches `$booking` from the DB immediately after `do_action('bookit_after_booking_confirmed')` fires, before passing it to `apply_filters('bookit_confirmation_meeting_section', '', $booking)`. This means the `$booking` array received by both filter callbacks already contains the `meeting_link` value written by the link generator — the extension no longer needs to re-read it from the DB itself. This task removes the manual DB re-read from both `confirmation_page_section()` and `confirmation_email_section()`, replacing each with a simple array read. The test helper must also be updated so tests pass the `meeting_link` value directly in the array rather than relying on the DB re-read that no longer exists.

**Important:** The KNOWN GOTCHA "Task reads a `$booking` array passed by a core filter → always re-read required fields from DB" applied to core versions before v1.5.1. It does NOT apply here — this task is explicitly removing that pattern because core now handles the re-fetch. Do not add a DB re-read; the whole point of this task is to remove one.
