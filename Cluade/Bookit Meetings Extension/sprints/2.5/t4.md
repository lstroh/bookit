## CONTEXT

The extension currently injects its Vue mount point div (`<div id="bookit-meetings-app"></div>`) before `</body>` using an `ob_start()` + `str_replace` approach hooked on `bookit_dashboard_loaded`. Core v1.5.1 has added `do_action('bookit_dashboard_extension_content')` inside the dashboard layout container (`dashboard/app/index.php`), after `<div id="app">` and before `</body>`. Switching to this hook places the mount div inside the core layout rather than below it, which is required for the Vue app to render correctly within the dashboard UI. This task removes the `ob_start()` mount div injection and replaces it with a direct `add_action('bookit_dashboard_extension_content', ...)` callback.

**Critical:** Read the existing `ob_start()` callback carefully before removing anything. If it handles both mount div injection AND JS script injection in a single callback, only the mount div injection must be removed — the JS script injection via `ob_start()` must be kept, because `wp_enqueue_script()` and `wp_footer()` do not work on the Bookit dashboard template (it does not call `wp_footer()`). Do not remove any `ob_start()` that is responsible for injecting `<script>` tags.

**Step 2 — Remove mount div injection via `ob_start()`.**

Remove only the portion of the `ob_start()` callback that injects `<div id="bookit-meetings-app"></div>`. If the callback does nothing else, remove the entire `ob_start()` call and its callback. If the callback also handles JS script injection, split it: keep the JS injection via `ob_start()`, remove only the mount div injection logic.

**Step 3 — Add `bookit_dashboard_extension_content` action.**

Add a new `add_action` callback that echoes the mount div directly:

```php
add_action( 'bookit_dashboard_extension_content', function() {
    $uri = $_SERVER['REQUEST_URI'] ?? '';
    if ( strpos( $uri, '/bookit-dashboard/app/meetings' ) === false ) {
        return;
    }
    echo '<div id="bookit-meetings-app"></div>';
} );
```

Register this action in the same method where the existing dashboard hooks are registered (e.g. `init()`, `register_hooks()`, or equivalent — read the file to confirm the pattern).

**Step 4 — Verify no direct echo on `bookit_dashboard_loaded`.**

The `bookit_dashboard_loaded` action fires before `<!DOCTYPE html>` in `index.php`. Any direct `echo` inside a `bookit_dashboard_loaded` callback will break the document. Confirm that no callback registered on `bookit_dashboard_loaded` echoes directly — all output on that hook must go through `ob_start()`.
