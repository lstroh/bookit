## CONTEXT

Task 1 delivers all PHP backend wiring required for the Sprint 2 Vue dashboard: asset enqueuing, JS data injection, and extending the booking API response with the meeting link. This task has no Vue components — it is pure PHP, and all new code must be hooked in through the existing loader pattern. The `bookit_dashboard_loaded` action (and nothing else) controls when extension assets are enqueued. The `bookit_booking_response` filter must re-read `meeting_link` from the DB rather than trusting the `$booking` array, because the array may be assembled before the link is written by a preceding hook.

## IMPLEMENTATION REQUIREMENTS

### `bookit-meetings/includes/class-bookit-meetings-loader.php` — MODIFY

Read the current file from GitHub before making any changes. Add three new hook registrations inside the method that registers the plugin's action and filter hooks (follow whichever registration pattern — `add_action` / `add_filter` — is already used in this file):

**Hook 1 — asset enqueue:**
- Hook: `bookit_dashboard_loaded` action
- Callback: a new private method `enqueue_dashboard_assets()` on this class (or a dedicated assets class — follow whatever pattern the loader already uses for class/method organisation)
- The callback must:
  - Use `wp_enqueue_script()` to enqueue the compiled Vue app JS (`dashboard/dist/assets/*.js`) using `plugin_dir_url()` to build the URL
  - Use `wp_enqueue_style()` to enqueue the compiled Vue app CSS (`dashboard/dist/assets/*.css`) using `plugin_dir_url()` to build the URL
  - Use `plugin_dir_path()` to check with `glob()` whether the dist files exist before enqueuing — if the dist directory is empty (i.e. Vite has not been built yet), skip silently and log a warning via `Bookit_Logger::warning()`
  - The script handle must be `'bookit-meetings-dashboard'`
  - The style handle must be `'bookit-meetings-dashboard'`
  - Do NOT enqueue at `init`, `admin_enqueue_scripts`, or `wp_enqueue_scripts`

**Hook 2 — JS data:**
- Hook: `bookit_dashboard_js_data` filter
- Callback: a new private method `add_dashboard_js_data( array $data ): array`
- The callback must merge the following keys into `$data` and return it:
  - `meetings_enabled` — read from `{prefix}bookings_settings` using the `get_col()` pattern (see KNOWN GOTCHAS); cast to boolean; key `'meetings_enabled'`
  - `meetings_platform` — read from `{prefix}bookings_settings` using the `get_col()` pattern; return as string; key `'meetings_platform'`
  - `meetings_manual_url` — read from `{prefix}bookings_settings` using the `get_col()` pattern; return as string; key `'meetings_manual_url'`
- **Settings read pattern (mandatory — do not deviate):**
  ```php
  $results = $wpdb->get_col( $wpdb->prepare(
      "SELECT setting_value FROM {$wpdb->prefix}bookings_settings WHERE setting_key = %s LIMIT 1",
      $key
  ) );
  return empty( $results ) ? $default : (string) $results[0];
  ```
  Never use `get_option()`. Never use `$wpdb->get_var()`.
- The JS data is passed to the Vue app via `wp_localize_script()` inside the same `enqueue_dashboard_assets()` callback, under the object name `bookitMeetings`

**Hook 3 — booking response:**
- Hook: `bookit_booking_response` filter
- Callback: a new private method `add_meeting_link_to_booking_response( array $response, array $booking ): array`
- The callback must:
  - Extract `$booking_id = (int) $booking['id']`
  - Re-read `meeting_link` **directly from the DB** using `get_col()` pattern — do NOT read from `$booking['meeting_link']` (the array may be stale — see KNOWN GOTCHAS)
  - Add `'meeting_link'` key to `$response` with the value (empty string if no link exists)
  - Return `$response`
