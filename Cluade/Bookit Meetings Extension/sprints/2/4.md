## HOW CORE RENDERS THE BOOKING DETAIL

Core's booking detail is a modal or panel triggered when a staff member clicks
a booking. It fetches booking data from:
```
GET {apiBase}/bookings/{id}
```
or from the bookings list endpoint. The URL changes to include the booking ID
as a query param or hash segment when a booking is open.

The extension cannot hook into core's booking detail render directly. Instead:
- The extension's Vue app watches `window.location` for a booking ID in the URL
- When a booking ID is detected, it fetches that booking from the core API
- It renders the Meeting Info section in `#bookit-meetings-app`

Read `bookit-booking-system/dashboard/src/` to find how core sets the booking
ID in the URL when a booking detail is open (look for `router.push`, query
params, or hash changes in booking-related components). Report what you find
before implementing the URL-watching approach.

### `dashboard/src/views/BookingDetailView.vue` — CREATE

This view is responsible for:
1. Detecting the active booking ID from the URL or DOM
2. Fetching the booking from `GET {restBase}bookings/{id}` (core endpoint)
3. Passing booking data to `MeetingInfoPanel.vue`
4. Showing a loading state while fetching
5. Showing nothing if no booking is active or if `meetings_enabled` is false

REST call:
```js
const url = `${window.BOOKIT_DASHBOARD.restBase}bookings/${bookingId}`
const response = await fetch( url, {
    headers: {
        'X-WP-Nonce': window.BOOKIT_DASHBOARD.nonce,
    }
} )
```

The response will include `meeting_link` (added by Task 1's
`bookit_booking_response` filter) and `customer_phone` (from core's booking
response — confirm the exact field name by reading the API class).

### `dashboard/src/components/MeetingInfoPanel.vue` — CREATE

A panel that renders meeting information for staff viewing a booking.

Props:
- `booking` (Object) — the full booking object from the API

Display logic:

**When `meetings_enabled` is false (read from `window.bookitMeetings`):**
- Render nothing (`v-if="false"`)

**When platform is `teams` or `generic` and `meeting_link` is non-empty:**
- Section heading: `"Meeting"`
- A "Join Meeting" link: `<a :href="booking.meeting_link" target="_blank">Join Meeting</a>`
- Copy-to-clipboard button next to the link

**When platform is `whatsapp`:**
- Section heading: `"Meeting"`
- Text: `"WhatsApp — call or video at appointment time"`
- Customer phone number displayed (read from `booking.customer_phone` or equivalent field name — confirm from API class)
- A `tel:` link on the phone number for click-to-call

**When platform is empty or meetings disabled:**
- Render nothing

**CSS:**
- Use `var(--bookit-bg-card)` for panel background
- Use `var(--bookit-color-primary)` for the Join Meeting link/button
- Use `var(--bookit-text-primary)` and `var(--bookit-text-secondary)` for text
- Use `var(--bookit-border-color)` for borders
- No hardcoded colours
